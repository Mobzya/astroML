# AstroML: рабочие инструкции

Читайте README.md, research/STATUS.md, research/research_plan.md и reports/recovery_audit.md в начале каждой сессии. Исторический master prompt: archive/handoff-2026-11-01/sources/CODEX_MASTER_PROMPT_RU.md; он не подтверждает выполнение работ. Применяйте релевантные .agents/skills.

- Основная цель: воспроизводимое исследование и самостоятельная защита участником.
- Не выдумывать результаты, ссылки, прочитанные статьи, команды и авторский вклад.
- Состояния: REPORTED_ONLY, RECONSTRUCTED, VERIFIED, PLANNED, BLOCKED. VERIFIED относится только к конкретной проверке, не ко всему исследованию.
- Исторические отчёты сохранять неизменными; старые evaluation не использовать для настройки новых методов.
- Разделять данные по исходному событию/latent pair до масок и аугментаций. Truth недоступен inference.
- PSPL event не означает чёрную дыру. BIC не вероятность класса. Oracle не практический алгоритм.
- Новые эксперименты: протокол → CPU smoke → проверки → freeze → evaluation → verifier → отчёт.
- Сохранять неудачи, несходимость, все seeds, выборки и знаменатели метрик.
- Записывать SHA кода, clean/dirty, версии, seed, config, hashes, runtime и независимое число источников.
- Не менять thresholds по evaluation; не открывать reserved final test для разработки.
- Публичный репозиторий разрешён владельцем 01.11.2026; платные ресурсы и письма третьим лицам не разрешены.
- Не коммитить токены, персональные документы, raw большие наборы данных.
- После значимого этапа обновлять README, STATUS и журнал решений. Финал: сделано / проверено / ограничения / следующий шаг.
- Не создавать субагентов без явного запроса пользователя.
