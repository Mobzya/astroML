## 1. ПРЕДМЕТ И МАТЕМАТИЧЕСКАЯ ПОСТАНОВКА
Рабочее название: «Исследование устойчивости физико-нейросетевых методов обнаружения событий гравитационного микролинзирования по неполным и зашумлённым фотометрическим рядам».

Изучить модель point-source point-lens (PSPL / Paczyński):
  u(t) = sqrt(u0^2 + ((t-t0)/tE)^2)
  A(u) = (u^2+2)/(u*sqrt(u^2+4))
  F(t) = Fs*A(u(t)) + Fb + noise(t)
Параметры: t0, u0>0, tE>0, Fs>0, Fb (предметно обосновать допустимую область), ошибки измерений sigma_i, временные метки t_i. Физически корректные нормировки и гетероскедастичность. По возможности независимая численная проверка на MulensModel; не устанавливай тяжёлое ПО без причины.

В первом релизе НЕ утверждать, что по одной фотометрической кривой определена чёрная дыра или масса линзы. Признать вырождение по массе, расстояниям и собственному движению. Двойные линзы, параллакс, finite-source effects — только расширения после завершения основной задачи.

Поставить задачу BINARY DETECTION: 1 = PSPL-like microlensing, 0 = научно правдоподобные альтернативы (постоянные звёзды с шумом, вспышки, затмения, пульсации, артефакты). Вторичная задача: fit параметров PSPL и количественная оценка их неопределённости. Классы RMDC26 не автоматически служат 0: многие являются разными типами микролинзирования. Проверить реальную семантику классов, доступность, лицензии и размер набора.

## 2. ОСНОВНЫЕ ВОПРОСЫ И ГИПОТЕЗЫ
H0: простая PSPL-подгонка и сильные ML baseline уже могут быть достаточно хороши; наша модификация не гарантирует превосходства.
H1: качество обнаружения снижается особым образом при пропуске пика относительно случайных пропусков той же доли.
H2: адаптивное объединение физического показателя соответствия и прогноза ML по признакам информативности наблюдений может улучшить recall при ФИКСИРОВАННОМ FPR на заранее определённых OOD-сценариях относительно каждого компонента и простого постоянного ансамбля.
H3 (опционально): характеристики неопределённости PSPL-параметров повышают надёжность gating/отказа от предсказания сравнительно с эвристиками только доли пропусков.
Каждая гипотеза проверяется независимо. «Новое решение» — не то же самое, что архитектура без аналогов: провести полноценный поиск литературы до заявления новизны. Допускаются нулевые/отрицательные результаты; фиксировать границы применимости.

## 4. ДАННЫЕ И ОТСУТСТВИЕ УТЕЧЕК
Первый baseline: небольшой собственный PSPL генератор плюс независимые фоновые/не-MLE контрпримеры. Добавить разумные параметры: t0, tE, u0, Fs/Fb, baseline drift при необходимости, Gaussian/Poisson-inspired шум в явно документированной модели, irregular cadence, seasonal gaps, missing peak, false transients. Генератор контрольных альтернатив должен быть достаточно богатым, но каждая группа явно документирована.
Сплиты по ORIGINAL EVENT / SOURCE ID / физических семействам; разные симуляции шума одного и того же события всегда в одном сплите. Train, validation и один LOCKED TEST (никаких подборов по test). Несколько независимых seeds. Никаких идентификаторов класса или инженерных артефактов генератора среди input features. Контролировать баланс, честно моделировать редкость события; при работе с RMDC26 проверить `final_weight` и влияние на репрезентативность. Negative pool должен содержать трудные случаи, включая имитации симметричных вспышек. Делать отдельные ID / split manifest и тест на leakage.
Сценарии OOD: 
A = изменение SNR; B = случайные пропуски; C = пропуск окрестности t0; D = изменение cadence; E = новый шум/новый источник данных (если доступен); F = другие классы переменности.
Не формировать финальный проект только на синтетических позитивных сигналах против белого шума. Не заявлять реальную эффективность без реального независимого теста.

## 5. BASELINES, ПРОВЕРКИ И ПРЕДЛАГАЕМЫЙ МЕТОД
Baseline-0: constant-flux null model, threshold/reference approach.
Baseline-1: PSPL nonlinear least-squares fitting (scipy.optimize), сравнительный score по fit vs альтернативы; явные bounds и robust initialization; учитывать degeneracy и computational budget.
Baseline-2: RandomForest/XGBoost на честных статистических features и physics residuals (нет доступа к истинным параметрам симулятора во время inference).
Baseline-3: 1D-CNN или небольшой TCN с учётом временных координат/masks/uncertainties; код поддерживает CPU quick-run и CUDA Kaggle.
Baseline-4: простой фиксированный ансамбль (валидационные/одинаковые настройки), чтобы сложный gating сравнивался с достойной альтернативой.
Candidate: adaptive physics-guided mixture: две калиброванные компоненты `p_physics` (калиброванный статистический score, НЕ считать p-value автоматически вероятностью класса) и `p_ml`, gating weight w(D) in [0,1] из допустимых observation-only features; калибровать итоговые вероятности только на validation/calibration subset, без использования теста. Избегать gating, который видит истинный класс, параметры симуляции или факт искусственной маскировки. Сравнить с простым logistic stacking; определить заранее точные критерии, что считать содержательным улучшением. Если метод проигрывает — честно сохранить результат.

## 6. METRICS И РЕПРОДУЦИРУЕМОСТЬ
Primary metric: event-level recall/TPR at fixed false positive rate (например 1%, если достаточное количество независимых negatives позволяет содержательно оценить), threshold выбирается ТОЛЬКО на validation; если тестовая выборка мала, пересмотреть FPR и обосновать.
Secondary: PR-AUC, ROC-AUC с оговорками, precision, F1, calibration ECE/Brier, runtime/event, memory, PSPL parameter recovery MAE/coverage (secondary only). Делать uncertainty via bootstrap at EVENT level (без подмены независимых событий точками временного ряда), seeds >=3 по возможности, confidence intervals, sanity checks.
Ablations: remove physics, remove gating, fixed gating, remove uncertainty, different negative pools. Сравнения при одинаковом бюджете обработки/обучения. Независимые тестовые конфигурации. Записывать `run_id`, git SHA, package versions, seed, exact config, data manifest, hardware, runtime, stdout, result JSON/CSV и figures. Не рисовать придуманные «примеры результатов»: synthetic illustrations маркировать.
